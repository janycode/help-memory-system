# 展示统一采用 Element Plus 原生能力自建展示层，不引入第三方后台模板

## 背景与决定

前端已使用 Element Plus 2.13.7，缺失的不是组件库，而是共享的展示契约：页头在 15 个文件里各写一遍且分成两种互斥流派，分页块有 6 份逐字重复，样式块内积压 433 处硬编码色值。决定以 Element Plus 官方组件与 theme-chalk 设计令牌为唯一母版，在 `src/components` 自建三个薄展示层组件（PageContainer、PageHeader、PaginationBar），不引入任何第三方后台模板。

## 考虑过的方案

**第三方 Element Plus 后台模板**（vue-pure-admin、vue-element-plus-admin 等）。开箱即用，但要求对齐甚至升级 Element Plus 版本，且其布局体系与现有路由、菜单权限、store 结构差异很大，接入必须改动 script，与本次的改造边界直接冲突。

**只统一全局 CSS，不抽组件**。改动最小，但消除不了 5 份重复的搜索栏与 6 份重复的分页块，缺少强制约束，几个月后必然再次发散。

## 后果

- 统一成本由【引入依赖并对齐版本】转为【收敛既有用法】，不新增依赖，不动 Element Plus 版本。
- 页面骨架由三个组件的 props 与插槽约定承载。新增页面必须复用，否则会成为新的发散源。
- 令牌层以 Element Plus 语义变量为底层，暗色模式由变量切换获得，无需逐页手写 `html.dark` 规则。
- 选择本方案后，再引入第三方模板的迁移成本高：页面骨架、令牌命名、组件契约都需整体替换。这正是记录本条 ADR 的原因。
